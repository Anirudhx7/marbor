Features

Built for production LLM workloads

Not a toy proxy. Built to the standard of a platform engineer with real GPU clusters, real SLAs, and real API bills.

Warm-first GPU routing

Polls each node's /api/ps every 2 seconds. Routes to the node that already has your model loaded in VRAM, eliminating cold-start latency entirely.

Cloud overflow fallback

When your local cluster is saturated or offline, requests automatically fall back to OpenAI or Anthropic. Ollama-native requests get response translation back to NDJSON - transparent to the client.

Cost tracking with receipts

Parses real token counts from every response. See exactly what you saved routing to local GPUs vs paying cloud API rates - down to the dollar, per request, per API key.

Per-key auth and quotas

API keys with per-model allow-lists, daily and monthly hard limits, token-bucket rate limiting, and durable quota persistence across restarts. No bypass possible.

VRAM telemetry

Live used-VRAM per node summed cluster-wide from each node's /api/ps. Total capacity from nvidia-smi (local) or declared config (remote). Every figure labelled by source.

Single Go binary, zero deps

One static binary runs everywhere. No Python, no Docker required. Embeds the admin dashboard. Starts in under 100ms. Your ops team can drop it on a server and go.

How it works

Replace OLLAMA_BASE_URL. That's it.

Point your OpenAI-compatible client or Ollama client at ollama-mesh instead of directly at your Ollama node. The routing is invisible to the caller.

1

Client sends request

Any OpenAI-compatible client (LangChain, llama-index, raw SDK) sends to :11434 with a Bearer token. ollama-mesh validates the key and checks quotas.

2

Router picks the best node

Finds all nodes with the requested model already warm in VRAM. Picks the one with the fewest active connections. Falls back to least-connections across all healthy nodes if no warm node exists.

3

Proxies and streams

Reverse-proxies to the chosen node with no response buffering. On node failure before first byte, retries alternate nodes, then cloud. Tracks tokens and logs cost per request.

Client (OpenAI SDK / Ollama client) | | POST /api/chat Bearer sk-... v ollama-mesh :11434 [Auth] [Rate limit] [Quota check] | | model = "llama3.2" v Router (polls /api/ps every 2s) |-- node-a: llama3.2 warm, 1 conn <-- SELECTED |-- node-b: llama3.2 cold, 0 conn |-- node-c: unreachable |-- cloud-fallback: OpenAI (only if all nodes fail) | v node-a :11434 (streaming NDJSON, no buffering) | v Admin :8080 tokens logged, cost tracked, VRAM updated
Get started

Up in 60 seconds

Zero-config first run: ollama-mesh auto-detects localhost:11434, generates API keys, and prints the endpoint URL.

# Download the binary for your platform curl -fsSL https://raw.githubusercontent.com/Anirudhx7/ollama-mesh/main/install.sh | sh # Or grab a release binary directly # https://github.com/Anirudhx7/ollama-mesh/releases # Run with zero config (auto-detects local Ollama) ./ollama-mesh # Output: # Admin dashboard: http://localhost:8080 # Proxy endpoint: http://localhost:11434 # API key: sk-mesh-XXXXXXXXXXXXXXXX # Point your client at ollama-mesh instead of Ollama directly export OPENAI_BASE_URL=http://localhost:11434/v1 export OPENAI_API_KEY=sk-mesh-XXXXXXXXXXXXXXXX

Prefer Docker? docker run -p 11434:11434 -p 8080:8080 ghcr.io/anirudhx7/ollama-mesh:latest
