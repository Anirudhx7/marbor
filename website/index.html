Stop sending requests to cold GPUs.

ollama-mesh is a smart proxy for your local inference fleet - Ollama, vLLM, TGI, or llama.cpp. Your engineers are already running DeepSeek-R1, Llama 3.1, and Qwen3 on local GPUs - models that rival GPT-4 at zero cost per token. ollama-mesh routes each request to the node that already has the model warm in VRAM, and falls back to OpenAI or Anthropic only when your cluster is saturated - tracking every dollar on the way.

Built for platform engineers

Everything you need to make one AI endpoint for the whole team.

No orchestration to babysit. Point your apps at one URL and ollama-mesh handles the routing, the failover, and the accounting.

Warm-first routing

Sends each request to a node that already has the requested model resident in GPU memory. No multi-second cold load, no thrashing models in and out of VRAM.

Cloud fallback that pays for itself

When every GPU is busy, requests overflow to OpenAI or Anthropic so nobody gets a 503. The moment your cluster frees up, traffic comes back home.

Cost tracking with receipts

Every fallback request is priced per token and logged. The dashboard shows exactly what you spent on cloud APIs - and what you saved by serving locally. Hard numbers you can put in a budget review.

Embedded admin dashboard

Live GPU utilization, per-model traffic, and spend - served straight from the binary. No separate web app, no Grafana to stand up. Open a port and it's there.

One static binary

Drop a single file on a box and run it. No Python runtime, no Docker, no dependency tree to audit. Cold-starts in under 100ms, so restarts are invisible.

OpenAI-compatible API

Speaks the /v1/chat/completions spec your tools already use. Continue, LibreChat, Open WebUI, and your own services connect by changing one base URL.

Any inference backend

Nodes can be Ollama, vLLM, TGI (Text Generation Inference), llama.cpp, or any OpenAI-compatible endpoint. Set runtime: vllm (or tgi, llamacpp) per node - /v1/* routes to any backend, /api/* stays Ollama-only. GPU VRAM metrics are Ollama and nvidia-smi; vLLM/TGI nodes show operator-declared capacity.

From zero to routed in three steps

It's a proxy. You point things at it.

No control plane, no agents on every node. ollama-mesh talks to your Ollama instances over their normal HTTP API.

1

Install the binary

Grab the release for your platform - or build from source with Go. It's one file with no runtime dependencies.

# one line, no sudo needed
curl -fsSL https://raw.githubusercontent.com/Anirudhx7/ollama-mesh/main/install.sh | sh
2

Point it at your nodes

List your nodes and, optionally, a cloud key for fallback. Ollama, vLLM, TGI, and llama.cpp nodes all work - set runtime: per node.

# mesh.yaml
nodes:
  - name: ollama-gpu
    url: http://gpu-01:11434
    runtime: ollama
  - name: vllm-gpu
    url: http://10.0.1.20:8000
    runtime: vllm
fallback: openai  # optional cloud overflow
3

Send traffic to one URL

Repoint your apps to the mesh. Same OpenAI-compatible endpoint - the routing happens behind it.

# your app, unchanged otherwise
base_url = "http://mesh:8080/v1"
# warm node picked automatically
